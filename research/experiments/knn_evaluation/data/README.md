# Synthetic metadata tables (`m1` and `m4`)

These are the generation tables used by the field-recovery and
metadata-completeness experiments. One row is one **metadata field** generated
for one (query, run, dataset) triple — not one dataset.

| File | Rows (original) | Compressed | SHA-256 (`.gz`) |
|---|---:|---:|---|
| `m1_synth_bio_mds.csv.gz` | ~26 MB CSV | 0.9 MB | `cf9150412372d2c1623ce3451d4f1ce593c64c11b52034dcbed00b95deef970d` |
| `m4_synth_bio_mds.csv.gz` | ~61 MB CSV | 2.4 MB | `abc1728d98be7830ef7eaf0fcc749096aa217e806e0b489dc710704096ed82e9` |

`m1` is the single-call generator (13 columns: query, run, dataset, field,
type, timing and token counts). `m4` is the DAG-augmented generator (18
columns: the same plus `node_id`, `node_name`, `node_descr` provenance).

## Decompress before running the experiments

The experiment code expects plain `.csv` files:

```bash
python prepare_data.py
```

That writes `m1_synth_bio_mds.csv` and `m4_synth_bio_mds.csv` next to the
archives. Pandas can also read the `.gz` files directly
(`pd.read_csv("m1_synth_bio_mds.csv.gz")`) if you prefer to keep them
compressed.

## Provenance

Generated by the `m1` and `m4` generators in
`research/experiments/knn_evaluation/generators/` from the 16 biomedical
queries in `research/experiments/knn_evaluation/queries/bio_queries.yaml`.
The notebooks in `ipynb_datagen/` show the generation and inspection steps.
