<a id="1-what-this-tool-is"></a>
## 1. Что представляет собой этот инструмент

SciDataMAS — это плагин DSH, который хранит **научное озеро данных** на вашей машине. Озеро содержит датасеты. Датасет имеет:

- имя, описание, назначение, статус и происхождение (provenance);
- схему метаданных (поля с типами, описаниями, единицами измерения и признаком обязательности);
- строки метаданных — по одной на файл или на строку таблицы;
- сами артефакты;
- журнал аудита и, необязательно, отчёт о валидации.

Вы работаете через агента в чате и наблюдаете за озером на панели **Data**. Агент использует инструменты; в этой версии панель доступна только для чтения.

<a id="2-before-you-start"></a>
## 2. Перед началом работы

Вам потребуется:

- рабочий профиль DSH (`web` — профиль по умолчанию для панели);
- настроенный маршрут модели в DSH (плагин использует модель сессии);
- каталог для озера с достаточным объёмом дискового пространства;
- примеры файлов для реалистичной проверки (несколько изображений, CSV или небольшая папка).

Плагин не хранит API-ключи. Вызовы модели идут через `ctx.llm`, поэтому действуют те же настройки провайдера, что и для остальной части DSH.

Рекомендуемый корневой каталог для тестов:

```text
/home/<you>/data/scidatamas
```

Не указывайте в качестве корня `/`, ваш домашний каталог или каталог с посторонними файлами. Плагин создаёт внутри него `datasets/`, `logs/`, `staging/` и `_imports/`.

<a id="3-install-and-configure"></a>
## 3. Установка и настройка

<a id="option-a-plugin-manager"></a>
### Вариант A: менеджер плагинов

```bash
dsh plugin --profile web add file:$PWD
```

`pnpm` должен быть доступен. Бандл включается автоматически.

<a id="option-b-manual-symlink-no-build-step"></a>
### Вариант B: символическая ссылка вручную (без шага сборки)

```bash
mkdir -p "$DSH_HOME/profiles/web/node_modules"
ln -sfn "$PWD" \
  "$DSH_HOME/profiles/web/node_modules/scidatamas-dsh-plugin"
```

Добавьте в файл `$DSH_HOME/profiles/web/cordis.patch.yml`:

```yaml
- insert:
    - id: scidatamas
      name: scidatamas-dsh-plugin
      config:
        root: /home/alex/data/scidatamas
        author: Your Name
```

### `dsh` не находится в PATH (Linux)

DSH может запускаться из npx-кэша или desktop-сборки, поэтому команды `dsh` в PATH может не быть — пакет `dsh` из apt к DSH отношения не имеет. Найдите настоящий CLI:

```bash
find "$HOME/.npm/_npx" -path '*/node_modules/.bin/dsh' -print
```

Запускайте его по абсолютному пути или задайте alias:

```bash
alias dsh="$(find "$HOME/.npm/_npx" -path '*/node_modules/.bin/dsh' -print -quit)"
dsh --version
```

Для установки через менеджер плагинов также нужен `pnpm`. Если его нет, запустите установщик по симлинку — он аккуратно правит патч профиля и создаёт корень озера:

```bash
./scripts/install-local.sh
```

Если профиль не `~/.dsh/profiles/web`, заранее задайте `DSH_HOME` и `DSH_PROFILE`.

Перезапустите профиль Web (или дайте HMR применить патч). Спросите агента:

> Покажи `scidatamas_status`.

Вы должны увидеть корневой каталог, драйвер хранилища, количество датасетов, доступность модели и лимиты.

<a id="configuration-reference"></a>
### Справочник по конфигурации

| Поле | По умолчанию | Описание |
|---|---|---|
| `root` | `.scidatamas` | Каталог озера: абсолютный или относительный к рабочему каталогу процесса. |
| `author` | пусто | Автор по умолчанию, записываемый в строках метаданных. |
| `provider`, `model` | пусто | Необязательное переопределение маршрута модели. Пустое значение означает «использовать модель сессии». |
| `maxSchemaFields` | `200` | Жёсткий лимит на количество генерируемых полей. |
| `maxDagNodes` | `24` | Жёсткий лимит на количество узлов DAG. |
| `dagConcurrency` | `3` | Параллельные вызовы генерации по узлам. |
| `debateRuns` | `3` | Количество прогонов дебатов по умолчанию. |
| `debateRoles` | `4` | Роли рецензентов на прогон. |
| `debateQuestionsPerRole` | `4` | Вопросов на роль за прогон. |
| `maxFileBytes` | `512 MiB` | Максимальный размер файла, копируемого в озеро. |
| `maxDownloadBytes` | `2 GiB` | Максимальный суммарный объём внешнего импорта. |
| `maxFilesPerAdd` | `200` | Файлов на вызов добавления или импорта. |
| `maxRowsScan` | `200000` | Строк, сканируемых из таблицы. |
| `allowNetwork` | `true` | Включает внешние импорты. |
| `allowPrivateHosts` | `false` | Разрешает импорт с localhost и частных IP-адресов. |
| `storageDriver` | `local` | `local`, `s3`, `synology` (последние два — точки расширения). |
| `logLlmCalls` | `true` | Записывать промпты и ответы в `logs/llm-calls.jsonl`. |

<a id="4-the-data-panel"></a>
## 4. Панель Data

Пункт боковой панели **Data** открывает панель, содержащую:

- список датасетов с поиском;
- метрики датасета (записи, файлы, версия схемы, компоновка);
- **Schema** — имя поля, тип, область действия, обязательность, единица измерения, описание;
- **Validation** — покрытие, полезные и неиспользуемые поля, вопросы без ответа, уточнения, предложенные поля;
- **Samples** — строки метаданных и ссылки на артефакты;
- **Content** — полная таблица метаданных с заголовками колонок, счётчиком строк, пагинацией и скачиванием CSV;
- **Events** — создание, staging, коммит, валидация, поиск, импорт;
- **Refresh** и **Copy id**.

Чтобы не терять диалог, нажмите **Открыть рядом с чатом** в шапке панели (или выберите Data в меню добавления правого sidebar). Панель закрепится справа, а основная колонка вернётся к чату.

Панель читает данные через `/scidatamas/api` и доступна только тому же владельцу (owner peer), что и остальная часть Web GUI. Если панель показывает **model unavailable**, хранилище продолжает работать; недоступны только генерация и валидация.

<a id="5-create-a-dataset"></a>
## 5. Создание датасета

Сформулируйте запрос на естественном языке. Инструмент выбирает агент. Хороший запрос содержит:

- имя;
- что представляет собой одна строка или элемент;
- как были получены данные;
- предполагаемое повторное использование;
- примеры путей, если они есть.

Пример:

> Создай датасет `confocal_cells_2026` из `/data/exp1`. Описание: конфокальные z-стеки клеток HeLa, фиксированных PFA, 40×, один стек на поле зрения. Назначение: повторное использование для сегментации клеток. Используй компактную схему и покажи мне поля.

Инструмент изучает примеры и возвращает черновик со схемой. По умолчанию датасет находится в состоянии **draft**.

Для многоэтапного эксперимента попросите богатые метаданные:

> Эксперимент включает пробоподготовку, конфокальную съёмку и сегментацию в Cellpose. Создай датасет с помощью расширенного процесса DAG.

`scidatamas_create_dataset_dag` создаёт больше полей и добавляет `node_id`/`node_description`; полей будет больше, чем нужно для любого повторного использования.

<a id="6-validate-a-schema"></a>
## 6. Валидация схемы

> Проведи валидацию дебатами в три прогона для `confocal_cells_2026` и покажи вопросы, на которые схема не может ответить.

Отчёт содержит:

- **coverage** — доля пользовательских полей, ответивших на вопрос рецензента;
- **useful fields** — сколько раз каждое поле использовалось и в скольких прогонах;
- **unused fields** — кандидаты на удаление или на более подробное описание;
- **unanswered questions** — пул пробелов;
- **clarifications** — конкретные вопросы исследователю;
- **suggested fields** — предлагаемые дополнения с именами и типами.

Схема не изменяется. Используйте уточнения, чтобы решить, что добавить.

<a id="7-refine-and-activate"></a>
## 7. Доработка и активация

> Добавь `pixel_size_nm`, `objective` и `fixation`; дополни описание словами «фиксировано PFA, пермеабилизовано»; установи статус «active».

`scidatamas_update_dataset` увеличивает `schema_version`, очищает `validated_schema_version` и фиксирует изменение. Для удаления полей требуется `allow_removals=true`.

Активировать датасет следует только после проверки схемы. Панель показывает `draft`, `active` или `archived`.

<a id="8-add-data"></a>
## 8. Добавление данных

<a id="review-first"></a>
### Сначала проверка

> Добавь `/data/exp2` в `confocal_cells_2026`. Пока не коммить. Примечание: 4% PFA, объектив 40×/1.3 oil, размер пикселя 100 нм.

`scidatamas_add_data` с `dry_run=true` или `commit=false` возвращает **stage**: предложенные метаданные для каждого файла, недостающие обязательные поля и предупреждения. При этом ничего не копируется.

<a id="commit"></a>
### Коммит

> Закоммить stage с этими значениями.

`scidatamas_commit_add` строго перепроверяет каждую запись. Если обязательное поле всё ещё отсутствует, коммит отклоняется и файлы не копируются.

<a id="explicit-values"></a>
### Явные значения

Можно передать объект значений, применяемый ко всем файлам, массив, выровненный по файлам, или отображение `file → values`. Значения, заданные пользователем, имеют приоритет над значениями, заполненными моделью.

<a id="if-the-agent-cannot-annotate-a-field"></a>
### Если агент не может разметить поле

Это нормально. Ответьте текстом:

> Пропущенное значение `fixation` — «4% PFA в течение 15 мин при комнатной температуре»; `z_slices` равно 31.

Затем выполните коммит с `metadata_overrides`; уточнение сохраняется в журнале аудита.

<a id="9-retrieve-data"></a>
## 9. Поиск данных

> Найди все конфокальные стеки с размером пикселя меньше 150 нм, созданные после марта, и покажи пути к файлам.

Процесс поиска выбирает датасет, планирует JSON-фильтр, проверяет имена полей и возвращает строки вместе с полными путями к файлам. Если план не удаётся построить, используется лексический резервный вариант; ответ сообщает об этом в `plan.used_fallback`.

Установите `include_preview=true`, чтобы получить короткие текстовые фрагменты или размеры изображений. Вкладка Samples на панели ссылается на сам артефакт.

<a id="10-import-from-zenodo-or-a-url"></a>
## 10. Импорт из Zenodo или по URL

Начните с анализа:

> Проанализируй запись Zenodo 5512749. Сколько файлов, какие форматы, какая лицензия?

Затем выполните импорт с фильтрами:

> Импортируй `**/*.tif` из этой записи, не более 20 файлов. Создай датасет из метаданных записи и активируй его.

Что происходит:

1. запись читается через API Zenodo;
2. выбранные файлы скачиваются в `_imports/<id>/`;
3. файлы анализируются и генерируется схема;
4. создаётся датасет (или используется существующий `dataset_id`);
5. DOI, лицензия, авторы и дата публикации сопоставляются со схемой;
6. файлы помещаются в staging и коммитятся;
7. при успехе staging удаляется, при ошибке сохраняется для анализа.

Прямые HTTP(S)-ссылки на файлы проходят тот же путь. Частные хосты блокируются, если не указано `allowPrivateHosts: true`.

<a id="11-tabular-datasets"></a>
## 11. Табличные датасеты

Используйте `layout="table"`, если основной артефакт — таблица:

> Создай табличный датасет из `/data/measurements.csv`; первый столбец — `participant_id`. Опиши каждый столбец.

Правила:

- таблица остаётся каноническим артефактом в `files/`;
- схема описывает столбцы (`scope: "column"`) и необязательные поля уровня строки;
- для каждой строки таблицы в `metadata.jsonl` хранится одна строка метаданных (sidecar) с ключом строки;
- `get_data` объединяет столбцы и строки sidecar;
- ключ строки выбирается из `id`/`row_id`/`row`/`index`/`sample_id`/`key`, затем первый уникальный столбец, затем индекс строки;
- разметка существующих строк поддерживается; добавление новых строк — пока нет.

<a id="12-where-the-data-lives"></a>
## 12. Где хранятся данные

```text
<root>/
  catalog.json
  datasets/<id>/
    manifest.json
    metadata.jsonl
    metadata.csv
    files/...
    events.jsonl
    validation/latest.json
    validation/history.jsonl
    staging/<stage_id>.json
  logs/llm-calls.jsonl
  _imports/<import_id>/
```

`manifest.json` — источник истины для схемы и состояния датасета. `metadata.jsonl` — хранилище строк. `metadata.csv` — плоский экспорт. `events.jsonl` — журнал аудита. `logs/llm-calls.jsonl` содержит внутренние промпты и ответы, если включён `logLlmCalls`.

Резервируйте копию всего корневого каталога; не редактируйте `manifest.json` вручную, пока сессия выполняет запись.

<a id="13-troubleshooting"></a>
## 13. Устранение неполадок

| Симптом | Вероятная причина | Что делать |
|---|---|---|
| `SCIDATAMAS_NO_MODEL` / «model unavailable» | Не выбрана модель сессии и не настроены provider/model | Выберите модель в DSH или задайте `provider`/`model` в конфигурации плагина. |
| `SCIDATAMAS_NO_LLM` | В профиле нет сервиса `ctx.llm` | Используйте Web-профиль с подключённым базовым бандлом. Инструменты, работающие только с хранилищем, по-прежнему работают. |
| Панель показывает «No datasets yet» | Пустое озеро или устаревший каталог в долго работающем сервере | Создайте датасет, затем нажмите Refresh. |
| `SCIDATAMAS_MISSING_FIELDS` | Коммит при отсутствии обязательных полей | Прочитайте список отсутствующих полей; передайте `metadata_overrides` или уточняющее примечание. |
| `SCIDATAMAS_FILE_TOO_LARGE` | Файл превышает `maxFileBytes` или `maxDownloadBytes` | Увеличьте лимит или сузьте импорт. |
| `SCIDATAMAS_PRIVATE_HOST` | Импорт с localhost или частного IP-адреса | Установите `allowPrivateHosts: true`, если доверяете источнику. |
| `SCIDATAMAS_BAD_JSON` | Модель не вернула корректный JSON после повторных попыток | Повторите попытку; если ошибка сохраняется, используйте более сильную модель или уменьшите лимит полей. |
| `SCIDATAMAS_NO_DATASET_MATCH` | Поиск не смог выбрать датасет | Передайте `dataset_id` явно. |
| `SCIDATAMAS_TABLE_REQUIRED` | `layout="table"` без `table_path` | Укажите путь к CSV/TSV/JSON/JSONL. |
| `SCIDATAMAS_SCHEMA_REMOVAL` | Обновление удаляет поля | Подтвердите с `allow_removals=true`, если это задумано. |

Другие коды перечислены в [TOOLS.md](TOOLS.md).

<a id="14-faq"></a>
## 14. Частые вопросы

**Видит ли модель мои исходные файлы?**  
Нет. Плагин передаёт имена файлов, форматы, размеры файлов и изображений, заголовки таблиц, структуру JSON и короткие текстовые фрагменты. Двоичное содержимое модели не отправляется.

**Где хранятся мои API-ключи?**  
Нигде в плагине. Он использует сервис LLM DSH и учётные данные профиля.

**Можно ли пользоваться этим без веб-панели?**  
Да. Инструменты работают в headless-режиме и в других профилях; клиентская часть доступна только в Web.

**Могут ли несколько человек писать в одно озеро?**  
Пока нет, это небезопасно. Блокировка каталога действует в пределах процесса. Используйте один процесс DSH на озеро; межпроцессная блокировка запланирована.

**Можно ли перенести озеро?**  
Да, если ни один процесс DSH не выполняет запись. Скопируйте весь корневой каталог и обновите `root`. Ключи в манифесте относительные, поэтому копия переносима.

**Работает ли это сейчас с S3 или Synology?**  
Нет. Интерфейс хранилища и заглушки есть; реальные драйверы — следующий шаг разработки.

**Схема метаданных хранится в CSV или в JSON?**  
Схема хранится в `manifest.json`; строки — в `metadata.jsonl`; `metadata.csv` — экспорт для удобства.
